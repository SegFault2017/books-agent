# Glossary — System Design Interview (Alex Xu)

**301 / 302 redirect** — permanent (browser caches; lower load) vs temporary (every hit reaches server; analytics) (Ch 8)
**ACID** — atomicity, consistency, isolation, durability; native in relational DBs (Ch 15)
**Anti-entropy** — repair replicas by comparing data, using Merkle trees (Ch 6)
**API gateway** — managed middleware for rate limiting, SSL termination, auth, IP whitelisting (Ch 4)
**APNs / FCM** — Apple / Firebase push services (Ch 10)
**Availability (nines)** — 99.9% ≈ 8.77 h/yr downtime; 99.99% ≈ 52.6 min (Ch 2)
**Back-of-the-envelope estimation** — rough capacity math from thought experiments + common numbers (Ch 2)
**Base 62** — encoding with [0-9a-zA-Z]; ID → short code (Ch 8)
**BLOB storage** — binary large objects stored as single entities (S3) (Ch 14, 15)
**Block server** — splits, compresses, encrypts file blocks ≤ 4 MB (Ch 15)
**Bloom filter** — space-efficient probabilistic membership test (Ch 6, 8, 9)
**CAP theorem** — at most two of consistency, availability, partition tolerance (Ch 6)
**CDN** — geo-distributed cache for static content; TTL controls freshness (Ch 1, 14)
**Celebrity / hotspot key problem** — one shard or user overloaded by excessive access (Ch 1, 5, 11)
**Codec / container** — compression algorithm (H.264, VP9, HEVC) / wrapper (.mp4, .mov) (Ch 14)
**Cold storage** — cheap storage for inactive data (S3 Glacier) (Ch 15)
**Consistent hashing** — hash ring, clockwise lookup; ~k/n keys move on resize (Ch 5)
**Content Seen? / URL Seen?** — crawler dedup by page hash / URL set (Ch 9)
**Coordinator** — node proxying client requests to replicas (Ch 6)
**DAG model** — transcoding tasks as directed acyclic graph stages (Ch 14)
**Delta sync** — upload only modified blocks (Ch 15)
**Eventual consistency** — replicas converge given time (Ch 6)
**Fanout on write / read** — push (precompute feeds) / pull (build at read) (Ch 11)
**Fixed / sliding window** — rate-limit counters per fixed window vs rolling window (Ch 4)
**geoDNS** — DNS resolving to nearest data center (Ch 1)
**GOP** — group of pictures; independently playable video chunk (Ch 14)
**Gossip protocol** — decentralized failure detection via heartbeat counters (Ch 6)
**Heartbeat** — periodic liveness signal; timeout → offline (Ch 6, 12, 15)
**Hinted handoff** — stand-in node returns writes to recovered node (Ch 6)
**HTTP 429** — Too Many Requests (Ch 4)
**Leaking bucket** — FIFO queue drained at fixed rate (Ch 4)
**Long polling** — server holds request until data or timeout (Ch 12, 15)
**Merkle tree** — hash tree for efficient replica comparison (Ch 6)
**Message queue** — durable async buffer decoupling producers and consumers (Ch 1, 10)
**Message sync queue** — per-recipient chat inbox (Ch 12)
**Pre-signed URL** — time-limited upload permission to one object (Ch 14)
**Quorum (N, W, R)** — replicas, write acks, read responses; W+R>N → strong (Ch 6)
**Read-through cache** — check cache, on miss read DB and populate (Ch 1)
**Robots.txt** — site rules for crawlers (Ch 9)
**Service discovery** — picks a chat server for a client (Zookeeper) (Ch 12)
**Sharding** — horizontal partitioning by sharding key (Ch 1, 13)
**Shard map manager** — lookup of which shard holds a key range (Ch 13)
**Sloppy quorum** — use first W/R healthy nodes (Ch 6)
**Snowflake** — 64-bit ID: 1 sign + 41 ts + 5 DC + 5 machine + 12 seq (Ch 7)
**SPOF** — single point of failure (Ch 1)
**SSTable** — sorted on-disk <key, value> file (Ch 6)
**Stateless web tier** — no session state on web servers (Ch 1)
**Token bucket** — tokens refilled at rate; request consumes one; allows bursts (Ch 4)
**Transcoding** — converting video to formats/bitrates (Ch 14)
**Trie** — prefix tree; cache top k per node for O(1) autocomplete (Ch 13)
**Vector clock** — [server, version] pairs to detect conflicting versions (Ch 6)
**Virtual nodes** — many ring positions per server for balance (Ch 5)
**WebSocket** — persistent bidirectional connection upgraded from HTTP (Ch 12)
